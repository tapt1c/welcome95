# Welcome95 1.0

Экран приветствия Windows 95 с компоновкой Windows XP, выбором сохранённых
пользователей и штатной проверкой пароля Windows. Нативный ANSI Win32/GDI,
x86/i386, без CRT, .NET и сторонних DLL.

Актуальная сборка: [скачать WELCOME95.EXE](https://github.com/tapt1c/welcome95/raw/refs/heads/main/build/welcome95.exe).
[Изменения версии 1.0](docs/RELEASE_1.0.md).

## Установка и обновление

Запустите скачанный `build/welcome95.exe` без параметров. В Windows 95/98/Me
он создаёт `%WINDIR%\LOGON`, копирует туда `WELCOME95.EXE` и открывает настройки
уже из установленной копии. Нажмите **«Включить»** и перезагрузите Windows.
После успешного применения в Панели управления появляется **Welcome95**. Значок
открывает те же настройки из LOGON и остаётся доступным после отключения экрана
входа, чтобы его можно было включить снова. Если Панель уже открыта, обновите
её или закройте и откройте заново. В упрощённой Панели Explorer95 переключитесь
на «Все параметры» для системного списка элементов.
[Устройство элемента](docs/CONTROL_PANEL.md).
Предпросмотры и запуск на других ОС не выполняют установку или смену автозапуска.

При запуске контроллер сначала показывает стартовый экран с системными шрифтами,
а затем читает профили и извлекает встроенные TTF. Подготовка ресурсов больше не
задерживает первый кадр; после неё применяется обычное оформление Welcome95.
Маленький загрузчик дополнительно показывает фон Welcome95 до запуска основного
EXE. При выходе из сеанса уже работающий контроллер удерживает фон ожидания до
готовности нового экрана входа. «Подождите...» и «Запуск Windows...» используют
одинаковые фон, свечение, границы полос и положение логотипа. Если Windows скрыла
ожидание или изменила разрешение при выходе, контроллер восстанавливает его до
готовности нового экрана; в неизменном состоянии перерисовок по таймеру нет.

Для обновления откройте старые настройки, нажмите «Отключить», закройте настройки
и предпросмотры, затем запустите новый скачанный EXE. Он обновит рабочую копию
в LOGON; предыдущая версия сохраняется как `E95xxxx.BAK`. После этого нажмите
«Включить» и перезагрузите Windows. Если установленный EXE занят, обновление
останавливается до изменения автозапуска. При переносе активной старой установки
из другой папки «Включить» проверяет её владельца и записи, сохраняет исходную
оболочку и перенаправляет запуск в LOGON. Ошибка возвращает прежние настройки.

В `%WINDIR%\LOGON` находятся:

- `WELCOME95.EXE`, маркер принадлежности `W95FILES.INI`;
- `W95xxxx.CPL` — небольшой посредник для значка Welcome95 в Панели управления;
- `W95xxxx.BAK` с исходной строкой оболочки и `E95xxxx.BAK` с предыдущим EXE;
- `welcome95-diagnostics.txt` и ограниченный журнал этапов `W95START.LOG`;
- собственные подкаталоги `W95xxxx.TMP` с ASCII-загрузчиком, временными шрифтами
  и PIF для DOS. Временные шрифты очищаются после завершения процесса; загрузчик,
  резервные копии и успешно переданный Windows PIF сохраняются для восстановления
  и ещё выполняющихся вызовов.

Старые файлы прежней установки автоматически не удаляются: они могут понадобиться
для восстановления или уже запущенного загрузчика. Новые записи и файлы работают
с LOGON. «Отключить» восстанавливает оболочку и завершает фоновые обработчики,
сохраняя резервные копии.

Без параметров открываются настройки **«Включить» / «Отключить» / «Просмотр»**.
«Просмотр» не принимает пароль и не меняет автозапуск; зелёная стрелка или
«Закрыть просмотр» показывает загрузку выбранной карточки и завершает просмотр.

## Оформление

Использованы оригинальные графические ресурсы предоставленного пользователем
XP `logonui.exe`: фон, логотип, аватар, подсветка карточки и кнопки. EXE XP не
запускается и не поставляется вместе с программой. Происхождение изображений:
[assets/README.md](assets/README.md). Суффикс логотипа заменён на 95 при рисовании.

Базовая компоновка — 800×600: верхняя полоса до y=78, нижняя с y=504,
разделитель x=398, логотип x=243, карточки x=425, имя/пароль x=499, стрелка x=685.
Размеры элементов не растут с разрешением: логотип 137×86, стрелка 26×26,
поле пароля 167×22 пикселя. Центральная группа перемещается относительно центра;
верхняя полоса остаётся высотой 78 пикселей, нижняя — 96. Список центрируется;
выбранная карточка показывает поле пароля. Шрифты учитывают системный DPI,
но не масштабируются пропорционально разрешению экрана.

## Пользователи и PWL

Программа собирает до 32 имён из:

- подразделов `HKLM\Software\Microsoft\Windows\CurrentVersion\ProfileList`;
- проверенных соответствий в `[Password Lists]` файла Windows `SYSTEM.INI`, если список профилей отсутствует;
- имени, уже сохранённого в настоящем окне входа; его написание имеет приоритет.

PWL-файлы **не открываются и не расшифровываются**. Это кэш паролей Windows 95,
а не самостоятельная база пользователей. Отсутствующий профиль с нестандартной
регистрацией может не попасть в список. Файлы PWL по имени файла не угадываются.

Для отдельных рабочих столов включите профили пользователей в настройках Windows
(Панель управления → Пароли → Конфигурация пользователей), затем выполните обычный
вход под нужными именами. Welcome95 показывает существующие записи; не создаёт
и не удаляет пользователей и пароли Windows. Все карточки пока используют общий
аватар. При числе пользователей больше четырёх появляются кнопки страниц.

Нажатие карточки меняет имя в настоящем окне Windows. Перед сменой имени старый
ввод пароля очищается. Это выбор пользователя **до входа**, а не быстрое
переключение уже запущенных пользовательских сеансов.

## Штатный диалог и вход

Собственного поля, копирующего пароль в другой процесс, нет. Настоящий диалог
Windows сохраняет своё поле пароля и обработчики. Исходные размер и стили
штатного диалога сохраняются; рамка и прочие элементы скрываются областью
обрезки. Видна только клиентская часть настоящего Edit внутри поля Welcome95.
Исходная кнопка OK тоже скрыта:
зелёная стрелка отправляет команду её настоящему идентификатору. Пароль остаётся
у Windows, не читается и не сохраняется Welcome95.

Встраивание больше не зависит от успешной регистрации Esc/Alt+F4. Геометрия и
скрытие поддерживаются по таймеру. Неподдерживаемая форма остаётся **под фоном**,
а не открывается автоматически поверх него. Аварийный возврат к полной штатной
форме сохранён, без отдельной кнопки на экране приветствия. Формы с доменом,
изменением пароля или неизвестными контролами требуют проверки.

Снимок исходных стилей, размеров, видимости и состояния контролов восстанавливается
при штатном выходе или ошибке размещения. Уже скрытый Windows диалог не открывается
заново. Принудительное завершение может потребовать перезагрузки для восстановления.

«Включить» сохраняет прежний `SYSTEM.INI [boot] shell` в реестре и в новом файле
`W95xxxx.BAK` рядом с EXE, затем ставит ASCII-загрузчик без аргументов; тот запускает посредник `/shell` через Win32. Постоянный `/welcome`
стартует через RunServices с тем же ASCII-загрузчиком. Синхронный `/startup` в RunOnce и посредник оболочки
используют раздельные сигналы: оболочка запускается за приветствием после входа,
а обычный автозапуск продолжается после закрытия экрана. Чужие записи не переносятся и не удаляются.
Системные RunServices работают в своём обычном порядке.

`/session-ready` в Run теперь служит уведомителем выхода из текущего сеанса.
Контроллер переживает logoff и показывает новый экран входа. Сигналы предыдущего
сеанса сбрасываются. После начала нового сеанса приветствие остаётся не менее
секунды, а подтверждение отправляется после фактического удаления окна.
RunServices асинхронен: появление перед самым первым системным диалогом не
гарантируется. Отмена входа Windows 95 также может начать сеанс; это не средство
ограничения доступа. Схема и восстановление: [docs/BOOT_FLOW.md](docs/BOOT_FLOW.md).

Порядок окон проверяется каждые 100 мс. Уже правильный порядок не меняется;
необходимые перестановки выполняются одним пакетом без перехвата фокуса. Ошибки
штатного входа остаются доступны выше фона. Перекрытие Ctrl+Alt+Del, критических
системных экранов и полноэкранного DOS не гарантируется. Кнопка выключения вызывает
окно выбора действий с затемнением. В «Просмотр» она не выключает систему.

## Сборка и проверки

```sh
# Debian/Ubuntu, с правами администратора:
apt-get install gcc-mingw-w64-i686 binutils-mingw-w64-i686 make
sh tools/build.sh
python3 tests/check_pe.py build/welcome95.exe
```

В подготовленной облачной среде инструменты находятся в `/workspace/.tools/mingw`.
Ресурсы встроены в EXE через windres; соседние BMP при запуске не нужны.
Проверка PE контролирует x86, подсистему 4.0 и импорты только системных DLL.

```sh
# Дополнительные тесты реальных Win32-окон под Wine64:
apt-get install wine wine64 xvfb gcc-mingw-w64-x86-64
sh tools/test-wine.sh
```

В облачной среде используется приватный Wine из `/workspace/.tools/win-tests`.
Прошли 465 проверок на каждом из трёх режимов экрана (см. ниже): размещение, полное скрытие рамки/OK, выбор имени,
очистка ввода, восстановление и порядок topmost. Проверен предпросмотр с тремя
вымышленными профилями в изолированном реестре Wine. **Межпроцессный ввод при
реальном входе Windows 95 и чтение её настроек PWL пока требуют проверки на месте.**

План проверки и аварийное отключение: [docs/TESTING.md](docs/TESTING.md).

## Диагностика «Preparing sign-in…»

Выбор карточки теперь сразу меняет интерфейс, даже если штатный диалог ещё
не подключён. До применения имени в Windows зелёная стрелка отключена.
Изменение имени выполняется отдельно от обработчика нажатия, с ограниченным
ожиданием и защитой от повторного входа в таймер. Пустое начальное имя разрешено,
если можно выбрать сохранённый профиль. Одинаковая геометрия не применяется заново.

При неудачном подключении рядом с EXE создаётся `welcome95-diagnostics.txt`:
причина отказа, классы контролов, IDs, стили и состояния. Текст полей, имена
пользователей и пароли в диагностику не записываются. Если вход остаётся неготовым,
этот файл поможет отличить неподдерживаемую форму от ошибки размещения.
Известные проблемы: [BAKCLOG.md](BAKCLOG.md). Правила работы: [AGENTS.md](AGENTS.md).

Исправление по диагностике Windows 95: скрытые **и одновременно отключённые**
поля и флажки больше не считаются активными параметрами входа. Их исходное
состояние сохраняется. Дополнительные поля, которые видимы либо включены,
по-прежнему требуют штатного диалога. Добавлен тест точной структуры из
14 контролов (классы, IDs и стили) из пользовательского лога.

## Загрузка сеанса и завершение работы

Экраны ниже относятся к этапу **после начала пользовательского сеанса**. До этого
пароль проверяет Windows через встроенное настоящее поле. При одном пользователе
сначала выполняется одна штатная попытка входа с пустым паролем; это не обход
аутентификации.

- Один пользователь после автоматического входа без пароля: только курсивное
  Welcome/Приветствие, без логотипа, карточек, разделителя и кнопок.
- После ручного экрана ввода, в том числе для единственного аккаунта: приветствие,
  выбранное имя, аватар и строка загрузки, как в XP. При VGA приветствие сверху,
  карточка ниже; при большем разрешении — две колонки. Несколько аккаунтов
  используют эту же композицию.
- Выключение: логотип Windows 95 по центру и сообщение о завершении работы.
  Неподтверждённые внутренние этапы вроде закрытия сетевых соединений не имитируются.

После запуска системного посредника экран приветствия остаётся не менее секунды.
Постоянный контроллер остаётся до выключения Windows и обрабатывает следующие
входы. Обычный процесс текущего сеанса передаёт ему уведомление logoff и выходит.
После подтверждённого выхода сбрасываются прежние сигналы и выбор; автоматическая
попытка входа больше не разрешается в этом процессе контроллера. Появляется
список аккаунтов без открытого поля, даже для единственного пользователя;
при отмене экран текущего входа сохраняется. Уведомление без причины обрабатывается
отдельно, без преждевременного завершения контроллера. «Отключить» останавливает оба
обработчика и восстанавливает прежнюю оболочку. **После обновления обязательно
выполните «Включить» новой версии и перезагрузите Windows.**

В компактных настройках есть предпросмотры «Запуск», «Без пароля», «С карточкой»,
«Выключение». Они закрываются через пять секунд и не выполняют вход или выключение.
Команды: `/preview-starting`, `/preview-single`, `/preview-multi`, `/preview-shutdown`.

[Один пользователь](docs/previews/single.png) ·

Русский интерфейс выбирается при ANSI-кодировке 1251;
иначе используется английский. Предоставленные Arial/Tahoma встроены в EXE:
отдельная установка шрифтов не требуется. Установленная копия извлекает их
в собственные временные подкаталоги LOGON; переносной предпросмотр использует TEMP.
Происхождение и механизм подключения: [assets/fonts/README.md](assets/fonts/README.md).
GDI проверил загрузку четырёх файлов и выбор Arial Bold Italic/Tahoma под Wine64;
таблицы имён выбранных начертаний побайтово совпали со встроенными файлами XP.
Фактические выключение, отмена и загрузка этих версий TTF на Windows 95 ещё
требуют проверки; системные запросы в тестах моделируются без реального выключения.

Шрифты обновлены предоставленными файлами из Windows XP: Arial Regular 3.00,
Arial Bold Italic 2.90, Tahoma Regular/Bold 3.15. Прежние версии 7.x заменены.

## Имена и режим 640×480

Daniel и DANIEL — одна учётная запись Windows 95. Для отображения сохраняется
написание из настоящего поля имени Windows (включая регистр), даже если кэш PWL
использует заглавные буквы. До подключения штатного диалога берётся имя профиля;
при совпадении без учёта регистра каталог профиля может уточнить его написание.
Путь профиля и тексты полей в диагностику не записываются.

При наличии зарегистрированных профилей посторонние PWL-алиасы не становятся
новыми карточками. В системе без списка профилей учитываются только корректные
имена с существующим PWL-соответствием; содержимое PWL не читается. Управляющие
и неопределённые символы не принимаются, обычные не-ASCII имена сохраняются.
Для русского текста выбирается системный charset, без слепого преобразования
всех имён из OEM в ANSI. OEM-алиас сопоставляется только с уже известным профилем.

Шрифты и элементы сохраняют размер при изменении разрешения; меняются их привязки.
Рисование идёт через двойной буфер; исходные RGB-битмапы выводятся через DIB
с явным COLORONCOLOR, без побитового смешивания соседних пикселей при уменьшении.
Видимая область ограничена клиентской частью поля высотой 22 пикселя; исходный
размер родительского диалога сохраняется.
В 16-битном цвете остаётся естественная ступенчатость градиента; 24/32 бита плавнее.

Выполнено 465 проверок под Wine64 в 640×480×16, 800×600×24 и 1024×768×24. Три пиксельных проверки
ищут цветовые выбросы в уменьшенном градиенте; десять проверок профилей используют
собственные временные registry/INI-данные, не реальные пользовательские профили.
Целевая Windows 95 всё ещё требует повторной проверки, особенно штатного поля.

## Выключение из приветствия

Turn off computer открывает компактное окно по образцу Explorer95: Stand By,
Turn Off, Restart, Restart in MS-DOS mode и Cancel. Фон плавно темнеет и теряет
цвет; само окно остаётся ярким. На русской Windows с ACP1251 подписи русские.
Cancel, Esc и Alt+F4 закрывают только окно выбора, возвращая приветствие и ввод.

Недоступные системные возможности отключены. Галочка MS-DOS выбирает именно
перезагрузку в DOS и отключает остальные действия. Выбранное действие выполняет
Windows без принудительного закрытия приложений. Затемнение снимается до вызова
ОС, чтобы можно было ответить на сохранение документов и отменить завершение.
Физическое отключение питания и ожидание зависят от поддержки APM компьютером.

`/preview-power` сразу открывает безопасный предпросмотр окна. В нём включены
демонстрационные кнопки; они не вызывают выключение, перезагрузку или DOS.
[Фактический снимок](docs/previews/power.png) ·
[источник реализации и ограничения](docs/POWER_SOURCE.md).

## Единственная учётная запись

При первом запуске Windows с одним обнаруженным аккаунтом показывается
«Запуск Windows…». После выхода из сеанса вместо автовхода требуется явно выбрать
аккаунт, даже единственный, и подтвердить вход. Это действует также при
уведомлении Win95 о конце сеанса без указания причины.
Размещение запуска и выключения общее: при 640×480 начало bitmap логотипа
(355,168), правый край текстовой области x=472, её верх y=274. Строка выравнивается
вправо, Arial 14pt — как в UIFILE оригинала. При смене разрешения эти позиции
перемещаются относительно центра экрана, без изменения размеров. Windows 95
на логотипе сохраняется. Welcome95 выбирает аккаунт и один раз отправляет штатную
команду OK с пустым паролем; оригинальные поле и форма на этом этапе не
перестраиваются. Если Windows принимает автоматический вход и сообщает о начале сеанса, появляется
Welcome/Приветствие без карточки. После секунды запускается сохранённая оболочка
за приветствием; экран убирается, когда оболочка начинает работу. После
ручного ввода отображается приветствие с карточкой даже для одного пользователя. До этого оболочка
остаётся за существующим шлюзом запуска. Запуск не изображает неподтверждённые
системные этапы вроде RPCSS.
Если нужен пароль, ошибка остаётся доступной, и вход продолжается вручную.
При неподдерживаемой/сменившейся форме или ожидании свыше четырёх секунд тоже
возвращается обычный экран ввода, без повторной автоматической попытки.
Если провайдер первоначально отключает OK для пустого ввода, попытка пропускается:
позднее включение кнопки не запускает автопопытку поверх ручного ввода.
Если поле уже редактировалось до подключения Welcome95, автопопытка также
пропускается по флагу изменения Edit, без чтения пароля.
Автоматических повторов нет; после отказа пользовательский ввод не очищается.
При двух и более аккаунтах автовход не выполняется. Неподдерживаемый провайдер
и явный переход к штатному диалогу также оставляют вход ручным.

Welcome95 не сохраняет пароль, не расшифровывает PWL и не включает автоматическую
отмену входа. Поэтому автовход в защищённый паролем аккаунт без его ввода не
предлагается. Реальная проверка конкретного сетевого клиента нужна на Windows 95.

## Компоновка 640×480

На небольшом экране используется вертикальный вариант XP: логотип и подсказка
сверху, список из двух видимых карточек ниже, прокрутка справа от списка.
При нескольких аккаунтах поле пароля раскрывается после нажатия имени.
Следующие аккаунты доступны через стрелки/ползунок прокрутки; запрос смены имени
по-прежнему обрабатывается отдельно от нажатия, без блокировки интерфейса.
Элементы сохраняют размеры. Полоса прокрутки использует оформление установленной
Windows. На больших разрешениях сохраняется расположение в двух колонках.

При загрузке выбранного профиля welcome/Приветствие располагается сверху, карточка
и статус — под ним. Нижняя панель остаётся высотой 96 пикселей.

## Мерцание и повторный вход

Убрана периодическая перестановка фона поверх настоящего поля пароля и обратно.
В неизменном состоянии поддержание приоритета не вызывает SetWindowPos; после
появления чужого окна фон, поле и сообщение Windows переставляются одним пакетом.
После подтверждённого входа оболочка с её окнами запускается за приветствием;
экран убирается без анимации при появлении окна оболочки. Ожидание ограничено
для оболочек без окна. Обычный автозапуск продолжает ждать закрытия экрана.

Новые проверки запускают посредники и искусственный диалог в отдельных процессах,
проверяют восстановление после logoff и отсутствие преждевременного подтверждения
при создании следующего экрана. Включены проверки резервной копии, отката и
восстановления произвольной исходной оболочки. Реальная загрузка Win95 остаётся
проверкой на целевой машине: [план](docs/TESTING.md), [восстановление](docs/BOOT_FLOW.md).


## Папка «Рабочий стол» и зависание после входа

Убрана передача пути основного EXE старому загрузчику SYSTEM.INI. Короткое имя
8.3 может содержать не-ASCII символы. Теперь «Включить» создаёт маленький загрузчик
в новом ASCII-каталоге на диске Windows; SYSTEM.INI получает путь к нему без
параметров. Основной EXE, в том числе из папки с кириллицей, запускается через
Win32. Задержки оболочки и автозапуска сохраняются.

После ручного возврата прежнего shell вход работает через старый сигнал Run,
поэтому задержка пропадает. Для новой схемы: «Отключить» старой версии, закрыть
настройки, заменить основной EXE, «Включить» новой версии, перезагрузка. Не переносить
основной EXE после «Включить». Резервная копия прежней оболочки сохраняется.

Скрытое `Ctrl+Alt+Shift+L` возвращает к существующей штатной форме Windows без
подсказок в интерфейсе и без автоматической отправки пароля. Рядом с основным EXE
в `%WINDIR%\LOGON` есть `W95START.LOG` с этапами и кодами, без содержимого полей.
Подробности:
[загрузка и восстановление](docs/BOOT_FLOW.md).


## Видимость поля и перерисовка после logoff

Проверка встроенного поля теперь учитывает само штатное Edit: видимость,
координаты, размер, стили и область обрезки. Если провайдер обновил свои контролы,
Welcome95 восстанавливает размещение поля, сохраняя ввод и исходного владельца.
Отключённые Windows поля и диалоги принудительно не включаются. Щелчок по белой
рамке передаёт фокус настоящему полю; после рисования фона Windows получает запрос
на его перерисовку в своём потоке.

Кнопки со своей отрисовкой полностью обновляются после рисования родителя и
закрытия затемнения. Обработчик сохраняет и восстанавливает состояние GDI DC.
Проверки включают реальные пиксели кнопки, повторное открытие/отмену выключения,
восстановление поля в отдельном процессе и отсутствие перестановок при простое.
Точное поведение провайдера и драйвера на Win95 требует повторной проверки в VM.


Исправлена ошибка загрузки `USER32.DLL:GetWindowRgnBox` на Windows 95.
Проверка области окна использует `GetWindowRgn` и `GDI32.GetRgnBox`, с отдельной
переиспользуемой областью для чтения. Исправления поля и кнопки сохранены.
Проверка импортов теперь отклоняет предыдущий несовместимый EXE.


## Клиентская область штатного окна Windows 95

Свежий лог показал отступ клиентской области `(3,22)` при сжатом до 22 пикселей
родительском окне: область пароля `(3,22)-(170,44)` оказывалась за его границей,
а hit test возвращал фон Welcome95. Теперь родитель сохраняет исходный размер,
рамку и стили. По измеренным отступам перемещается всё окно, а область обрезки
показывает только клиентскую часть настоящего поля. Собственные рамки Edit тоже
сохраняются и остаются за областью обрезки. Доступность ввода проверяется через
настоящие события мыши/клавиатуры и пиксели символа-маски в отдельном процессе.


## Полный русский интерфейс и крупные звёздочки

Переведены экран входа, подсказки, настройки, статусы, предпросмотры, сообщения
об ошибках и ошибки загрузчика. Русские строки хранятся в CP1251 для ANSI-окон
Windows 95; при других кодировках используется английский вариант.

Штатное поле пароля использует более крупный системный шрифт Windows. Видимая
область остаётся 167×22 пикселя. При возврате к стандартному диалогу возвращается
его прежний шрифт. Введённый пароль и обработчики Windows сохраняются.

## Ошибка включения автозапуска и журнал установки

При ошибке окно теперь показывает код и точный этап операции. Журнал
%WINDIR%\LOGON\W95START.LOG создаётся уже при начале настройки, даже если
Owner ещё не записан в реестр. Метки install-boot-* относятся к загрузчику,
install-recovery-* — к резервной копии, install-reg-* — к реестру,
install-shell-* — к SYSTEM.INI. Записываются только метки и числовые коды,
без имён пользователей, путей, команд или содержимого полей.

Для RegFlushKey ключ открывается с KEY_QUERY_VALUE вместе с правом записи.
Новый файл восстановления резервируется напрямую через CREATE_NEW; совпадение
имени с прежним .BAK выбирает другое имя, включая вариант ошибки 5 от Win95.
Настоящий отказ в записи останавливает установку и не считается успехом.
