# Welcome95

Экран приветствия Windows 95 с компоновкой Windows XP, выбором сохранённых
пользователей и штатной проверкой пароля Windows. Нативный ANSI Win32/GDI,
x86/i386, без CRT, .NET и сторонних DLL.

## Установка и обновление

Скопируйте `build/welcome95.exe` в постоянную локальную папку, например
`C:\WELCOME95`. При обновлении закройте настройки и замените EXE в той же папке.
Запуск без параметров открывает **Enable / Disable / Preview**. Enable добавляет
автозапуск; после этого перезагрузите Windows. Preview не принимает пароль и не
меняет автозапуск. Зелёная стрелка или Finish preview завершает предпросмотр.

## Оформление

Использованы оригинальные графические ресурсы предоставленного пользователем
XP `logonui.exe`: фон, логотип, аватар, подсветка карточки и кнопки. EXE XP не
запускается и не поставляется вместе с программой. Происхождение изображений:
[assets/README.md](assets/README.md). Суффикс логотипа заменён на 95 при рисовании.

Базовая компоновка — 800×600: верхняя полоса до y=78, нижняя с y=504,
разделитель x=398, логотип x=243, карточки x=425, имя/пароль x=499, стрелка x=685.
Координаты масштабируются под экран. Список центрируется; выбранная карточка
показывает поле пароля. Шрифты и их сглаживание зависят от установленной Windows.

## Пользователи и PWL

Программа собирает до 32 имён из:

- подразделов `HKLM\Software\Microsoft\Windows\CurrentVersion\ProfileList`;
- имён в секции `[Password Lists]` файла Windows `SYSTEM.INI`;
- имени, уже сохранённого в настоящем окне входа.

PWL-файлы **не открываются и не расшифровываются**. Это кэш паролей Windows 95,
а не самостоятельная база пользователей. Отсутствующий профиль с нестандартной
регистрацией может не попасть в список. Файлы PWL по имени файла не угадываются.

Для отдельных рабочих столов включите профили пользователей в настройках Windows
(Панель управления → Пароли → Конфигурация пользователей), затем выполните обычный
вход под нужными именами. Welcome95 показывает существующие записи; не создаёт
и не удаляет пользователей и пароли Windows. Все карточки пока используют общий
аватар. При числе пользователей больше четырёх появляются кнопки страниц.

Нажатие карточки меняет имя в настоящем окне Windows. Перед сменой имени старый
ввод пароля очищается. Это выбор пользователя **до входа**, а не быстрое
переключение уже запущенных пользовательских сеансов.

## Штатный диалог и вход

Собственного поля, копирующего пароль в другой процесс, нет. Настоящий диалог
Windows сохраняет своё поле пароля и обработчики; его рамка и прочие элементы
скрываются. Область окна обрезается до одного прямоугольника настоящего Edit,
размещённого внутри белого поля Welcome95. Исходная кнопка OK тоже скрыта:
зелёная стрелка отправляет команду её настоящему идентификатору. Пароль остаётся
у Windows, не читается и не сохраняется Welcome95.

Встраивание больше не зависит от успешной регистрации Esc/Alt+F4. Геометрия и
скрытие поддерживаются по таймеру. Неподдерживаемая форма остаётся **под фоном**,
а не открывается автоматически поверх него. Кнопка Trouble signing in? позволяет
явно вернуть полную штатную форму, если провайдеру нужны дополнительные поля.
Формы с доменом, изменением пароля или неизвестными контролами требуют проверки.

Снимок исходных стилей, размеров, видимости и состояния контролов восстанавливается
при штатном выходе или ошибке размещения. Уже скрытый Windows диалог не открывается
заново. Принудительное завершение может потребовать перезагрузки для восстановления.

`HKLM\...\CurrentVersion\RunServices`, значение `Welcome95`, запускает `/welcome`.
`HKLM\...\CurrentVersion\Run`, значение `Welcome95`, запускает `/session-ready`.
После сигнала старта сеанса экран ждёт не менее секунды и закрывается.
RunServices асинхронен: порядок появления раньше системного диалога не гарантирован.
Run означает старт сеанса, а не криптографическое подтверждение пароля; отмена
входа в Windows 95 также может открыть сеанс. Это не средство ограничения доступа.

Верхнее положение восстанавливается каждые 100 мс без перехвата фокуса. Ошибки
штатного входа остаются доступны выше фона. Перекрытие Ctrl+Alt+Del, критических
системных экранов и полноэкранного DOS не гарантируется. Кнопка выключения вызывает
штатное завершение работы после подтверждения. В Preview она не выключает систему.

## Сборка и проверки

```sh
# Debian/Ubuntu, с правами администратора:
apt-get install gcc-mingw-w64-i686 binutils-mingw-w64-i686 make
sh tools/build.sh
python3 tests/check_pe.py build/welcome95.exe
```

В подготовленной облачной среде инструменты находятся в `/workspace/.tools/mingw`.
Ресурсы встроены в EXE через windres; соседние BMP при запуске не нужны.
Проверка PE контролирует x86, подсистему 4.0 и импорты только системных DLL.

```sh
# Дополнительные тесты реальных Win32-окон под Wine64:
apt-get install wine wine64 xvfb gcc-mingw-w64-x86-64
sh tools/test-wine.sh
```

В облачной среде используется приватный Wine из `/workspace/.tools/win-tests`.
Прошли 45 оконных проверок: размещение, полное скрытие рамки/OK, выбор имени,
очистка ввода, восстановление и порядок topmost. Проверен предпросмотр с тремя
вымышленными профилями в изолированном реестре Wine. **Межпроцессный ввод при
реальном входе Windows 95 и чтение её настроек PWL пока требуют проверки на месте.**

План проверки и аварийное отключение: [docs/TESTING.md](docs/TESTING.md).

## Диагностика «Preparing sign-in…»

Выбор карточки теперь сразу меняет интерфейс, даже если штатный диалог ещё
не подключён. До применения имени в Windows зелёная стрелка отключена.
Изменение имени выполняется отдельно от обработчика нажатия, с ограниченным
ожиданием и защитой от повторного входа в таймер. Пустое начальное имя разрешено,
если можно выбрать сохранённый профиль. Одинаковая геометрия не применяется заново.

При неудачном подключении рядом с EXE создаётся `welcome95-diagnostics.txt`:
причина отказа, классы контролов, IDs, стили и состояния. Текст полей, имена
пользователей и пароли в диагностику не записываются. Если вход остаётся неготовым,
этот файл поможет отличить неподдерживаемую форму от ошибки размещения.
Известные проблемы: [BAKCLOG.md](BAKCLOG.md). Правила работы: [AGENTS.md](AGENTS.md).

Исправление по диагностике Windows 95: скрытые **и одновременно отключённые**
поля и флажки больше не считаются активными параметрами входа. Их исходное
состояние сохраняется. Дополнительные поля, которые видимы либо включены,
по-прежнему требуют штатного диалога. Добавлен тест точной структуры из
14 контролов (классы, IDs и стили) из пользовательского лога.
